## 最小目标布局

继续使用用户目录中的 PostgreSQL 16 服务，目标建议为独立数据库 `askdata_m2_bird`，保留官方 `public` schema 和原有表名，从而保留 PostgreSQL Gold SQL 原文。连接地址与端口沿用已核实服务的 `127.0.0.1:55432`，实施前重新确认；M1 的 `askdata_m1_test` 继续作为已有证据来源。

官方 dump 合并了 11 个逻辑域的 75 张表。本方案在独立 M2 数据库中创建 75 张表，每个逻辑域配置独立只读角色 `askdata_m2_ro_<db_id>`，只显式授予该域所属表的 SELECT。`database_id` 由服务端绑定到目标库、角色和授权表集合，模型不传连接串、密码或自行选择角色。

导入角色建议为 `askdata_m2_import`。初始化时由现有管理员创建独立库和受限角色；导入角色负责 DDL/COPY，查询角色无 CREATE、TEMP、写入或所有者权限。公共默认授权、schema CREATE 和默认权限需要显式核对，不能对全部查询角色执行“所有表可读”的公共授权。

## 实施顺序

1. **服务器预检。** 确认 PostgreSQL 服务、版本、当前用户权限、目标库尚不存在或为空，以及 `/home` 可用空间。源 SQL 大小约 956 MiB，目标表、索引、WAL 和临时文件另需空间；先制定容量预算，空间不够时不启动导入。
2. **来源预检与清单。** 上传所需 PostgreSQL SQL、75 份字段说明、表关系文件、冻结题目和协议清单；核对来源 SHA-256，保存每个表的 DDL、COPY 行数、索引、序列和约束清单。原 ZIP 可留在本地，不要求为导入再次上传全部混合数据库包。
3. **独立初始化。** 创建 M2 目标、导入角色和 11 个查询角色。凭据在服务器独立配置，报告只记录身份和是否配置，不写明文。建立目标意外重用、非空目标和错误库拒绝检查。
4. **受控导入实现。** 原 SQL 是纯文本 `CREATE/COPY` dump。显式审查并映射 99 处作者所有权声明，审查会话设置与权限语句；按已审查的语句类别执行，拒绝外部命令、文件读写及意外库/角色管理。不使用未经核对的全局文本替换修改数据区。导入失败记录事务和恢复状态，不覆盖旧报告。
5. **数据与权限核验。** 全部 75 表结构、类型、NULL、COPY 行数与目标计数核对；使用明确类型规范的完整行摘要验证数据，并核对约束、序列和索引。各查询角色只读操作、跨域 SELECT 拒绝、写入/临时对象拒绝和失败后连接恢复都需要实测。
6. **通用 runtime。** 根据 `db_id` 装配该域身份、授权 catalog/profile 和连接池；复用 M1 的只读事务、UTC、受控 search_path、超时与生命周期。索引、Gold 缓存、snapshot 和续跑身份纳入协议、域、角色及验证版本。索引内容只来自授权字段与允许的说明/取值，不能读取 Gold 或其他域的表。
7. **Gold 就绪门槛。** 保留原始 Gold，按各域只读角色执行选中的 110 题，使用完整原生行结果。确认 Gold 无超时、超限、权限、类型或执行错误后，才进入 smoke8 和开发集 live。

源 dump 的 COPY 计数为 3,898,114 行；这是源侧检查，目标计数与类型化摘要尚未建立。上述步骤应分别保存来源预检、导入、一致性/ACL、runtime 及 Gold 报告。
