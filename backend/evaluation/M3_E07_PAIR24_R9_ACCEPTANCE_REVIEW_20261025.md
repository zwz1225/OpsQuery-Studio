## 四题人工审查

### 1480：原生结果匹配，月度聚合语义未通过

两侧最终SQL完全相同：

```sql
SELECT SUBSTRING(ym.date FROM 5 FOR 2) AS month
FROM yearmonth ym
JOIN customers c ON ym.customerid = c.customerid
WHERE c.segment = 'SME'
  AND ym.date >= '201301' AND ym.date <= '201312'
ORDER BY ym.consumption DESC NULLS LAST
LIMIT 1
```

SME条件、2013日期范围、来源授权及关联均存在。两侧都得到授权的 `customers.segment`、关联键，以及 `yearmonth.date/consumption`；关系明确标为reviewed candidate，没有冒充数据库外键或强制join。

但SQL选取的是消费最大的单条客户月份记录。Gold先按月份分组，再按 `SUM(consumption)` 排序。两条逻辑在本快照中恰好都返回 `04`，因此原生比较通过，**不代表所需聚合已实现**。candidate的提示已经传入，但没有改变这道题的SQL。不能把本轮1480算作语义改善，也不能仅靠 `target_1480_native_correct` 和包含 `segment` 宣布目标通过。

后续应明确区分群体月度指标和单条记录最大值，并将实际分组/聚合计划作为验收依据。任何新增诊断或提示应来自公开问题与授权schema，不能把Gold片段送入模型。

### 0050：地址先于名称，当前结果通过，名称来源有证据边界

- baseline：`SELECT s.school, s.mailstreet ...`，列顺序错误；曾先生成不存在的 `sc.street`，经修复后仍把学校放在地址前。
- candidate：`SELECT s.mailstreet, sc.sname ...`，地址在前、学校名称在后；首次生成即通过校验。
- 两侧都按数学成绩 `DESC NULLS LAST LIMIT 1 OFFSET 6` 排名。
- candidate结果为 `('25 Churchill Avenue', NULL)`，与Gold当前完整结果一致。Gold输出的是 `schools.school`，candidate输出的是 `satscores.sname`。

**本轮确认输出顺序修正、原生匹配改善。** 两个名称字段当前均为NULL，只能证明当前结果一致，不能据此声称这两个字段在所有数据上可以互换，也不能说已经恢复出非空学校名称。

### 0459：最终SQL语义通过，多消耗一次修复

candidate只投影 `name`，按两张牌的名称筛选，再用 `convertedmanacost DESC NULLS LAST LIMIT 1` 排序；没有额外投影排名指标，返回 `Serra Angel`。

首次SQL缺少 `NULLS LAST`，被已有的 `nullable_order_nulls_first` 校验拒绝；第二次生成补齐后通过。baseline首次生成即正确。由此确认最终输出字段规则保持，但修复成本增加。

### 0173：继续失败，错误在数值角色和账号范围

两侧都在第二部分使用 `order.account_to = 3539`，把总金额误当作账号值，并且第二部分没有与账号3正确绑定。candidate返回 `('POPLATEK MESICNE', NULL)`；Gold返回 `('POPLATEK MESICNE', 'POJISTNE')`。

Gold需要按账号和用途汇总 `SUM(order.amount)`，并查找总额3539对应的用途。`order.amount` 已经出现在授权Schema图中，所以当前报告不支持将该失败简单归为字段未召回。该题继续作为已观察的语义遗留项。
