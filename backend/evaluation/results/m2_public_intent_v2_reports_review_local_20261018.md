## 三项遗留问题

### 0201：粒度修复有效，单位约定仍存在冲突

模型前两次 SQL 在 atom/bond 一对多连接后按行累计，校验反馈均正确指出重复计数。最终 SQL 使用 EXISTS，消除了关联倍增。

实际输出 `0.3880961092816197`，参考为 `38.80961092816197`。原始问题写 percentage，但官方 evidence 的 DIVIDE 公式没有写乘 100，参考 SQL 则乘了 100。因此不能仅用参考结果反推并强制植入单题规则，应先明确公开的比例/百分数约定和冲突处理。

在 Python 中将已返回浮点值乘 100 得到 `38.809610928161966`，与参考仍差 `7.105427357601002e-15`，即一个浮点最小间距。这不是 PostgreSQL 修改 SQL 的执行结果；下一步必须验证 SQL 中转换、缩放和除法的类型及顺序，保持原生评分无容差。

### 0586：关系角色已正确，输出上下文未落实

实际连接为 `users.id = votes.userid`，不再误选最后编辑者。两名用户 `chl`、`shabbychef` 与参考第一列一致。授权图和 contract 已包含 posts.title，以及 actor+context 输出建议，但 SQL 仅投影 displayname；参考有 displayname/title 两列。

另有 `ILIKE` 与参考 `LIKE` 的大小写语义差异。本次用户名结果一致，仍需独立比较这些筛选方式的完整用户/标题元组，不能仅凭用户名一致宣称条件完全等价。输出组建议是否应成为可见、通用的开发输出约定，需要明确适用边界，避免把参考投影硬编码到题号。

### 1399：维持参考形态差异记录

预测是单值 `Yes`；参考是 14 行中的 `YES` 与 NULL，去重后仍为两个元组。仅统一大小写仍不能解决 NULL/集合形态差异。继续按原生规则判错，独立保留语义审查，不删除 NULL、不改 Gold、不写题号特殊模板。
