## 当前最需要修复的实现问题

`intent.py` 的 `sample_conditions()` 将“原问题/evidence 的词或数字碰巧与授权样本值匹配”直接提升为 `required_profile_conditions`。字段存在、样本真实、来源授权，均不能单独证明用户要求该字段等于这个值。

四条实际反馈轨迹完整：模型首次生成未包含上述额外条件的 SQL → `missing_population_condition` 拒绝 → 第二次生成添加所要求条件 → SQL 执行成功但原生结果错误。这是本次候选实现引入的问题，不能归因于 PostgreSQL 可用性、服务器同步或模型没有服从反馈。

修复应从约束依据着手：明确字段与值的所属关系，区分公式数字、实体名称、表/角色名和业务分类值。样本匹配可帮助检索与候选解释，不能自动变成强制 WHERE。保留 1486 的 SME 覆盖收益时，也必须有清楚的字段—值语义依据。
